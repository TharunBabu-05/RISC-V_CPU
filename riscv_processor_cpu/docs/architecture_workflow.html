How one instruction becomes UART output

1. Boot

After BTN0 release and PLL lock, rst_n is synchronized. The PC starts at 0x00000000, where the VMEM image is loaded.

2. Pipeline

The instruction flows through IF, ID, EX, MEM and WB. The hazard unit can stall load-use dependencies; forwarding avoids unnecessary stalls; taken branches flush younger instructions.

3. Memory map

A load/store effective address is decoded. BRAM handles data addresses at 0x2000_0000; UART handles 0x1000_0000.

4. Serial TX

uart_putc polls TX_READY, writes one byte to offset 0x0, and the UART transmitter serializes it to the FPGA TX pin.

Recommended workflow

Develop

Edit reusable RTL under rtl/, FPGA integration under phase8/rtl/, and firmware under phase8/software/.

Simulate

From riscv_processor_cpu/, use make sim or targeted targets such as make sim_muldiv, make sim_mmu, make sim_fp, and make sim_vector.

Verify

Use make regress, make compliance, and make formal. These exercise different confidence layers; passing one does not replace the others.

Deploy

Build firmware, copy the selected VMEM with make program or make hello_program, reset Vivado synthesis, generate the bitstream, program the board, then open a 115200 8N1 terminal.

Source note: The FPGA RTL currently uses a 100 MHz UART parameter in phase8/rtl/soc_top.sv, while phase8/README.md documents a 25 MHz MMCM configuration. Confirm the generated Vivado clock/IP and UART clock parameter agree before relying on the exact baud rate.
